# AI Matrix — v10 Visualization & Catalog UX Overhaul

## Проблемы пользователя (цитата)
1. «всё как-то слишком хуёво выглядит в плане визуализации (cwe бенч)» — графики неинформативны.
2. «каталог со всеми ии тоже хуй поймёшь как выглядит, мне для него фильтрации» — каталог нечитаем, фильтры неочевидны.
3. «нельзя начать сортировать по чём-то, типа по статусу и/или SWE» — сортировка только через select, шапка таблицы не кликабельна.
4. «радар топ-5 по качеству выглядит точь-в-точь одинаково, за исключением 1% разницы — это неправильно» — баг нормализации.
5. «продумай и проработай лучше всё это — визуально, технически и функционально. Делаю каталог для себя, но может кому-то пригодится».

## Диагностика radar-бага (root cause)
Оси имели разные максимумы: SWE ≤ 75, HumanEval ≤ 100, Aider ≤ 80, ctx ≤ 1 048 576, out ≤ 524 288. Каждая вершина нормировалась к СВОЕМУ максимуму → все 5 топ-моделей имели почти идеальную форму (все близки к 100% по своей оси), поэтому полигоны визуально слипались. Разница 1% не читалась.

**Фикс:** три режима нормализации, переключаемые:
- `relative` — значение / max по оси во всём датасете (100% = лучший в датасете). Различия видны, но всё ещё сжаты.
- `spread` — min-max по оси среди сравниваемых моделей (min → 0, max → 100). Максимальное усиление различий; для топ-5 это то, что нужно.
- `raw` — абсолютные значения, подписи реальных чисел (для точного сравнения).
Плюс: подписи реальных значений на каждой вершине, легенда со score, и отдельный «gap to leader» dumbbell-график.

## План работ

### 1. Сортировка по клику на шапку
- `thead th` становятся кнопками; клик → asc/desc, повторный клик → реверс.
- Визуальный индикатор ▲/▼ + класс `sorted`.
- Сортируемые: # (rank), AI, ctx, out, SWE, HE, Aider, Провайдер, Статус, Тип.
- Select «Сортировка» остаётся как быстрый пресет, но шапка — главный путь.
- Сортировка по числовым колонкам должна использовать **числовое** сравнение (не строковое) — сейчас `sort` по SWE уже числовой, но по статусу — лексикографически (working > catalog > blocked > paid по алфавиту), что неудобно. Вводим порядок статусов: working → catalog → paid → blocked.

### 2. Фильтры — понятная структура
- Фильтры сгруппированы в подписанные блоки: **Провайдер · Статус/Тип · Задача · Качество · Размер**.
- Каждая группа — `<label>` + select.
- **Активные фильтры как чипсы** под панелью: «OpenRouter ×», «SWE ≥60% ×», каждая снимается кликом; + «Сбросить всё».
- Счётчик результата рядом с чипсами: «23 из 72 маршрутов».
- Пустое состояние → понятная подсказка + кнопка сброса (сейчас просто «Ничего не найдено»).

### 3. Переработанные графики (4 → 6)
Все — инлайн SVG, без CDN, с единым стилем: сетка, подписи осей, легенда, value-labels, hover `<title>`.
1. **Quality ladder (новый)** — горизонтальные бары топ-15 моделей по SWE с реальными числами и дельтой к лидеру. Заменяет нечитаемый radar как основной.
2. **Radar** — с 3 режимами нормализации (relative/spread/raw) + подписи значений + легенда со score.
3. **ctx × SWE scatter** — остаётся, но: цвет = статус маршрута, размер = out, подпись лидеров, оси с делениями.
4. **Матрица покрытия (новая)** — тепловая карта «модель × задача» (задачи: Кодинг/Reasoning/UI/Vision/Stealth/Long Context…), показывает какие задачи закрыты какими моделями. Это отвечает на «зачем мне каталог».
5. **Провайдеры: working/catalog/blocked** — stacked bar с процентами + счётчиками.
6. **Лимиты** — RPM/RPD/токены в день, горизонтальные бары с подписями.

### 4. Каталог — читаемость
- Zebra-строки, hover-подсветка, моноширинные числа с tabular-nums и правым выравниванием.
- Provider: цветной pill + точка статуса.
- Контекст: клик на «AI / семейство» → раскрывает все маршруты этой модели (список провайдеров) прямо в строке. Сейчас одна модель = несколько строк подряд, что визуально шумно. **Группировка**: строка семейства, под ней маршруты; toggle «Группировать по модели».
- Слева — цветной маркер семейства (rank-цвет), чтобы глаз цеплялся.

### 5. Каталог → персональный дашборд
- Быстрые пресеты в один клик: «Только рабочие», «Максимум ctx», «Лучшие по SWE», «Без ключа (no-auth)», «Stealth/preview».
- Эти пресеты — чипы над таблицей; комбинируются с фильтрами.

### 6. Технические улучшения
- `requestAnimationFrame`-батчинг рендера (сейчас перерисовка всей таблицы на каждый ввод в поиск — при 72 строках ок, но при росте каталога будет тормозить).
- `localStorage` для состояния фильтров/сортировки/режима radar + восстановление при возврате на страницу.
- Клавиатура: `/` фокус в поиск, `Esc` — сброс/закрыть панель колонок.
- `aria-sort` на сортируемых th, `aria-label` на иконочных кнопках.
- Кэш SVG-графиков и перерисовка только при смене данных.
